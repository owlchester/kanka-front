# i18n Design — kanka.io Marketing Site

## Overview

Add multilingual support (French, German, Spanish, PT-BR) to the Nuxt 4 static marketing site at kanka.io. English remains the default and source of truth. AI-powered automation keeps translations always in sync with English content. Images/screenshots stay English-only.

---

## Library & Module Setup

**`@nuxtjs/i18n` v9** (Nuxt 4 compatible).

Locale files: flat JSON at `locales/en.json`, `locales/fr.json`, `locales/de.json`, `locales/es.json`, `locales/pt-BR.json`.

`@nuxt/content` files move into locale subdirectories: `content/en/`, `content/fr/`, etc.

```ts
// nuxt.config.ts
i18n: {
  locales: ['en', 'fr', 'de', 'es', 'pt-BR'],
  defaultLocale: 'en',
  strategy: 'prefix_except_default',
  lazy: true,
  langDir: 'locales/',
}
```

`prefix_except_default` keeps English URLs unchanged (`/features`), adds prefix for others (`/fr/features`). No redirects needed for existing English URLs.

**Excluded pages** (English-only, no locale variant): `privacy-policy`, `terms-and-conditions`. Configured via `@nuxtjs/i18n` per-route exclusion.

**Template links:** All internal `<NuxtLink>` hrefs replaced with `:to="localePath('/path')"`. The composable resolves the correct locale-prefixed URL automatically. Links to excluded pages always return the unprefixed English URL.

**URL slugs:** Not localized (e.g., `/fr/features` not `/fr/fonctionnalités`). Complexity-to-SEO-benefit ratio is poor, especially for dynamic routes.

## SEO

`@nuxtjs/i18n` auto-injects hreflang alternates on every localized page:

```html
<link rel="alternate" hreflang="en" href="https://kanka.io/features" />
<link rel="alternate" hreflang="fr" href="https://kanka.io/fr/features" />
<link rel="alternate" hreflang="de" href="https://kanka.io/de/features" />
<link rel="alternate" hreflang="es" href="https://kanka.io/es/features" />
<link rel="alternate" hreflang="pt-BR" href="https://kanka.io/pt-BR/features" />
<link rel="alternate" hreflang="x-default" href="https://kanka.io/features" />
```

**Canonical:** Each locale variant canonicals to itself (not back to English). Google indexes all variants independently.

**`og:locale`:** Added to the existing `useSeo` composable, reading the current i18n locale and mapping to the correct Open Graph locale code (`fr_FR`, `de_DE`, `es_ES`, `pt_BR`).

**Sitemap:** Add `@nuxtjs/sitemap` — integrates with i18n and outputs all locale variants automatically.

## Automation Pipeline

**Trigger:** GitHub Action on push to `main`, watching paths `locales/en.json` and `content/en/**`.

**Two source types:**

1. **`locales/en.json`** — detect changed/added keys, retranslate only those keys for all 4 languages, merge into existing locale files. Avoids retranslating unchanged strings.

2. **`content/en/**`** — when a file changes, retranslate the whole file for all 4 languages (file-level granularity).

**LLM:** Claude Haiku 4.5 via Anthropic API. Fast, cheap (under $1 for a full retranslation of all content).

**Prompt constraints the system prompt must enforce:**
- Preserve JSON key names exactly
- Preserve markdown formatting
- Do not translate proper nouns: Kanka, TTRPG, D&D, app.kanka.io
- Do not translate component names or code blocks

**Commit strategy:** The Action commits translated files back to `main` with a `[bot] translate: <changed file>` commit message. Netlify picks up the commit and rebuilds.

**Translation drift manifest:** A `locales/manifest.json` file tracks `{ "content/en/faq/home.yml": { "fr": "2026-06-11T10:00:00Z", "de": "..." } }` — updated by the Action after each translation run. Used to audit drift without polluting content files.

## Language Detection

`@nuxtjs/i18n` browser language detection enabled, but configured for **suggestion only** — a dismissable banner ("Voir en français ?", "Auf Deutsch ansehen?") rather than an automatic redirect. Users can also switch locale via a language picker in the nav/footer.

---

## Migration Work (Upfront)

1. Extract all hardcoded text from ~20 `.vue` page templates into `locales/en.json` keys
2. Move all `@nuxt/content` files from `content/` into `content/en/`
3. Update all `queryContent()` calls to prefix with locale
4. Replace all hardcoded `<NuxtLink>` hrefs with `localePath()`
5. Add `@nuxtjs/i18n` and `@nuxtjs/sitemap` to `nuxt.config.ts`
6. **Remove** old locale redirect rules from `nuxt.config.ts` (`/fr/**` → `/gone`, etc.)
7. Add `og:locale` to `useSeo` composable
8. Write GitHub Action + translation script
9. Spot-check initial translations with native speakers before first launch

## What Stays English-Only

- `privacy-policy` and `terms-and-conditions` pages
- All images and screenshots
- `llms.txt` (generated by `nuxt-llms`)
- `gone.vue` / redirect routes
